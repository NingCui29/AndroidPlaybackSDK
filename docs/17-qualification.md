# Q02～Q04　格式、稳定性与性能验收计划

对应 M3。三项可并行，均以前置 H04、L01、L02 完成作为正式执行条件。采用同一候选构建及[设备角色](06-devices.md)、[样本编号](07-samples.md)、[指标定义](08-metrics.md)。当前全部未执行。

## Q02　逐格式验证

**建表粒度**：一行对应一个文件子编号、摘要、设备固件、输入方式与解码策略。先由产品确认必测集合，再计算覆盖率。D01 跑必测组合；D03 跑平台差异；D07 的高规格项需先确认承诺。自动模式记录实际后端，视频补测软解，已确认具备相应硬解能力的设备再测仅硬解。纯音频单列。

| 批次 | 实际操作 | 需要观察的结果 |
|---|---|---|
| V01～V05 常用容器 | 核对轨道、起播，暂停恢复，向前和向后定位，播放到尾再打开。V02 对标尺，V03/V04 采用相同轨道的重封装样本，V05 切双音轨 | 首帧、首声、方向、实际落点、选轨报号及尾音与样本标记一致 |
| V06～V10 Web、历史格式与 TS | 逐个子编号执行，记录真实编码变体及硬解回退；V10 跨越时间戳跳变 | 对照预期时长语义、声画恢复与尾部；单列“可解码”和“达到实时门槛” |
| V11 纯视频 | 观察可变帧率、长 GOP 定位及暂停位置；移除再绑定输出 | 无音轨时进度正确，恢复后首个有效帧属于当前时间轴 |
| A01～A06 纯音频 | 无 Surface 打开；核对封面、声道、定位、短尾音。分开执行 Vorbis/Opus 等子编号 | 音频输出完整，无多余视频会话；用回录核对标记 |
| X01～X03 边界 | 同内容分别从 URI、FD 区间、顺序源打开；负例对照预期错误；高规格按已批准设备单列 | 输入能力及错误与预期一致；4K、位深、码率、并发数记录实际值 |

**结果登记**：记录样本摘要、实际轨道与后端、各操作结果、日志或录制位置、缺陷编号。按“通过／失败／未执行／待判定／经确认不适用”分列；硬解不可用且仅软解跑通时，报告该路径及适用规格。修改支持范围需留存确认记录及变更前后的分母。Q02 完成要求必测行逐项有证据；失败关联缺陷和复验结果。

## Q03　异常、并发与生命周期

为每次操作登记会话、请求、时间轴、输出绑定版本、真实后端和单调时间。优先使用明确的触发时点复现；随机压力作为补充，记录随机种子与实际操作顺序。真实平台故障与注入结果分别归档。

| 场景 | 触发步骤 | 判定依据 |
|---|---|---|
| 权限与损坏 | 用 X02 分别打开无权限 URI、截断文件、异常元数据；随后打开 V01 | 拒绝、提前结束或故障符合各子样本约定；每个请求只终结一次，后续有效源可播 |
| 阻塞与背压 | X01 写端保持打开并停供，另测包队列填满；分别 stop、release | 被阻塞线程退出，回收 FD，无虚假 Ended；计入 K08 超时统计 |
| 快速切源 | A 源准备中打开 B，再让 A 的准备或错误事件迟到；在定位预滚期间重复 | B 的状态、声音及画面只归属 B；旧请求仍有终止结果 |
| 重建中退出 | V01 重绑 Surface 或重建 AudioTrack 时切源、release；软解与硬解各执行 | 旧输出引用归还、旧索引无重复操作、完成通知后无输出；用线程和窗口记录核对 |
| 换轨与恢复竞争 | V05 请求换轨，紧接着 seek 或暂停；另在硬解回退期间执行 release | 最后意图生效，活动轨与实际声音一致；恢复不重新激活已释放实例 |
| 双实例争用 | 两个实例同时启动、暂停与释放；分别使用自动和仅硬解策略。资源充足时记录双成功，另以受控注入触发不足 | 错误和回退归属正确实例；逐实例记录后端、影响和最终状态。实机未触发资源耗尽须注明 |

遇到挂起时保存最后事件、线程栈和等待资源，区分超过时限与已证实死锁。崩溃记录构建标识及符号化堆栈。修复后先按原顺序和同一输入复验，再测相邻场景。Q03 完成需逐例核对恢复状态、错误归属、资源退出与重复轮次，未触发的故障路径单列。

## Q04　性能、耐久与资源回收

先记录空闲宿主基线、供电、温控、输出路由、刷新率、后台负载和采集工具。所有轮次按设备、固件、样本、实际后端分组。启动、定位与释放沿用已确认的 Q01/K08；实时性、长播和资源水位的已确认门槛集中在[Q02～Q04 决策记录](19-decisions.md)。

| 测量组 | 执行步骤 | 交付记录 |
|---|---|---|
| K01～K03 启动与定位 | 冷组每轮重启进程，暖组同实例重新打开；缓存状态另记。建议各 30 次；定位前后各 15 次，覆盖长 GOP | 记录每轮起止、P50/P95、实际落点最大绝对误差；提交帧、实际可见、首个有效 PCM 分开 |
| K04/K05 同步与流畅度 | V01 外部同步采集闪光与短音，覆盖起播、恢复、定位；V01/V03/V07 分别连续播放，建议 3 轮 × 10 分钟 | 校准偏差、有符号同步差、绝对偏差 P95、应显示帧数、迟到丢帧率、最长连续卡顿 |
| K06/K07 占用与长播 | 建议以 1 秒间隔采 CPU、PSS、native heap；V01 和 A03 各 2 小时 × 2 轮。短样本循环时给边界打标 | 输出原始时间序列、峰值、稳态水位、后半程趋势、热降频时刻和中断；记录 CPU 百分比的核数口径 |
| K08 正常与阻塞释放 | D01 用 V01 正常播放、X01 停供，各建议重复 50 次。每轮在创建前、播放中、释放完成及固定空闲窗口末尾采样 | 绘制 FD、线程、活跃 codec、PSS/native heap 随轮次变化；分别记录 stop 与 release 的 P95、最大耗时、未退出资源与超时数 |

计算分位数时保存原始数据和样本数，失败、超时与取消单列。PSS 波动或单个峰值需与活跃资源数、稳态增长和回收后水位一起判断。参考设备未冻结阈值时仅出测量结果。确认异常后在相同固件、样本和输出路径复测，另作关闭高频诊断采集的对照，识别采集开销。

## 新增参数的执行口径

覆盖率分母在执行前登记；负例按预期错误通过，与正常可播率分列。固定种子压力用于补充指定时序；重复运行时保留操作间隔和事件记录。单路实时性逐轮判定，卡顿以预期持续出画时相邻可见帧的间隔测量，保留稳态阻塞时间。相对 CPU 增长使用相同条件下两个 P95 的比值；首测尚无参考或参考值接近零时单列原始值，不填“回归通过”。资源比较使用相同采样口径的空闲时间窗和预热宿主，关注多轮趋势。详见[七项已确认参数](19-decisions.md)。
