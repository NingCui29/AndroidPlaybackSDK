# Q01　软解闭环真机验收操作表

**执行前置**：B03、A03、S04、S05 已完成；准备含软件后端与诊断输出的独立宿主。当前状态为未执行。执行时引用[设备清单](06-devices.md)、[样本矩阵](07-samples.md)、[指标口径](08-metrics.md)和[软解设计](11-software-playback.md)。

## 准备与通用闭环

1. 选 D01 参考真机，登记系统、固件、ABI、显示刷新率、音频路由、SDK/宿主构建号、FFmpeg 标识及供电温控条件。清点样本并核对摘要。
2. 固定为仅软解。诊断记录实际解码器、输出像素或采样格式、会话号、时间轴版本及首帧/首声事件。有视频的用例须能证明该次实际使用软件后端。准备外部声画采集并校准采集偏移与精度；只有内部时间戳时，实际声画偏差记为未测。
3. 分别对 V01（有声视频）、A02（纯音频）、V11（纯视频）完整执行：打开 → 等待 Ready → 播放 → 暂停 → 恢复 → 前向定位 → 后向定位 → 自然结束 → 同实例再次打开播放 → stop → release。A02 全程不绑定 Surface；V11 全程无音频时钟。为每份样本单独保存状态轨迹。
4. 每轮记录输入动作、媒体位置、实际后端、可见帧号或可听标记及终止结果。首帧提交、实际可见、首个 PCM 被消费和实际首声分别采集。冷暖分组及统计轮次引用 K01～K04；一次功能跑通只登记功能结果。

## 专项步骤与判定

| 步骤 | 设备操作 | 可检查的预期及证据 |
|---|---|---|
| Q01-1 声道与尾部 | 播放 A04 左右声道报号，再让 A02 播到 EOF；保存输出回录 | 左右声道对应，A02 尾音完整。记录最后有效采样消费与 Ended 的顺序 |
| Q01-2 画面 | 播放 V02 和已登记的标尺/色阶变体，采集首帧与稳定帧 | 方向、四边、比例和灰阶符合参考，记录实际帧号；画面证据与 SDK 提交日志分别留存 |
| Q01-3 同步与暂停 | V01 在起播、稳态、暂停恢复和定位后采闪光与短音；中途静音再恢复 | 按 K04 扣除采集偏差并保存原始标记；静音期间进度前进，暂停期间保持 |
| Q01-4 长 GOP 定位 | 对 V11 选关键帧之间的前后目标；连续提交两个目标，第二次预滚中暂停 | 保存目标、实际帧号、落点和耗时；旧版本无晚到输出，最新目标可预览且保持暂停。A02 重做音频定位并核对声音标记 |
| Q01-5 排空与中断 | 自然播完带延迟帧视频；另起会话在尾部等待阶段主动停止；X01 管道停供时释放 | 自然结束只出现一次且尾帧存在；主动停止可再打开；停供释放按 K08 计时，无工作线程遗留 |
| Q01-6 失败回收 | 在独立测试宿主触发输出创建失败；重复调用 release 并比较会话前后 FD、线程及内存 | 错误阶段与原始原因可追溯，清理只发生一次，完成通知后无旧输出；保留异常和超时轮次 |

## K04 外部采集文件与评分

在同一时基采录 V01 的光、声以及独立校准信号。保留原始录制文件，按实际操作发生时刻区分起播、稳态、暂停恢复和定位后四个阶段。每阶段取十个不同的有效闪光／短音对，核对 V01 的标记表。允许恢复或定位回到已播放过的素材时间，记录中须能区分两次实际发生的事件。

| 文件 | 字段与单位 |
|---|---|
| 测量 CSV | 表头为 `round,phase,mediaMs,toneMs,flashMs,recording`。一次独立采集集使用 `round=1`，阶段依次为 `start`、`steady`、`resume`、`seek`。素材标记位置用 `mediaMs`，实际短音和闪光起点用采集时钟毫秒。 |
| 采集 JSON | `clock`、`method` 写明设备、接法和标记提取方法。`recordings` 将各原始文件的相对路径映射到 SHA-256，含校准录制。`calibrationRecording` 填对应路径，`calibrationOffsetMs` 的符号为采集链音频时间减光信号时间，`calibrationResidualMs` 填校准后残差。 |
| 关联信息 | `measurements` 与 `measurementsSha256` 指向 CSV。`apkSha256`、`fixtureSha256`、`instrumentationSha256` 分别对应已安装测试包、V01 和该轮 instrumentation.txt。`playbackRound` 使用日志中 `V01.mp4-<轮号>` 的实际轮号。各轮独立评分。 |

运行 `python tools/score-q01-sync.py --run <真机证据目录> --capture <采集JSON> --output <评分JSON>`。各阶段保留十个有符号偏差，按最近秩计算绝对值 P95。10 ms 校准残差、80 ms P95 和 150 ms 单标记上限按已确认值执行。评分器的控制样例已覆盖正常输入及七种异常，实际声画偏差等待 D01 共时基回录。[素材标记](../testdata/baseline/markers.csv) · [评分器控制记录](../artifacts/validation/20261113-144238-timings/progress/k04-scorer-check.json)
