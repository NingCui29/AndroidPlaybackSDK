# 实施计划与验收矩阵

开发任务、前置依赖和逐项验收见[按模块执行的 TODO 清单](05-todo.md)。

## 阶段与依赖

| 阶段 | 依赖与工作 | 完成条件 |
|---|---|---|
| M0 基线 | 确认设备、最低 API、ABI、必需格式、独立样本来源、远端仓库类型 | 形成带优先级的设备及样本清单，确定每项性能门槛的参考设备 |
| M1 软解闭环 | 基于 M0 实现输入、解封装、音频与视频软解、Surface、时钟、生命周期 | 带音轨视频、纯音频和纯视频均完成打开、播放、暂停、定位、自然结束及再次打开，保留真机证据 |
| M2 硬解闭环 | 基于 M1 完成码流适配、MediaCodec 选择、直出与回退 | 真机验证硬解成功、强制软解、初始化失败回退和运行中恢复 |
| M3 格式与稳定性 | 基于 M2 加入格式矩阵、切轨、并发、异常文件、资源预算 | 必需样本逐项通过或由产品确认降级范围，缺陷可由日志和样本复现 |
| M4 SDK 发行候选 | 接入契约稳定后准备构建配置，可与 M3 并行；发版依赖 M3 结果 | 三渠道独立宿主通过；文档与实际制品一致；发布批准另行记录 |

## 首批样本

| 类别 | 样本与覆盖重点 |
|---|---|
| 常用视频 | MP4/MOV + H.264 + AAC；MP4/MKV + HEVC + AAC；MKV 双音轨。覆盖 B 帧、长 GOP、旋转、音轨切换 |
| Web 视频 | WebM + VP8/Vorbis、VP9/Opus。区分软解成功与实时播放 |
| 历史视频 | AVI + MPEG-4 Part 2 + MP3、ASF/WMV + WMV3 或 VC-1 + WMA。记录 WMA 具体变体 |
| 传输流文件 | MPEG-TS + H.264 + AAC。覆盖时长未知、时间戳跳变、输入截断 |
| 音频 | MP3、M4A/AAC、FLAC、WAV/PCM、Ogg/Vorbis、Ogg/Opus、ASF/WMA，包含带封面的文件和短尾音 |
| 边界 | 纯视频、可变帧率、顺序管道、有限描述符区间、异常元数据、损坏文件、不可读 URI |
| 高规格 | 4K、10-bit、高码率、多实例。按设备与输出能力独立列项 |

每个样本登记来源与使用许可、摘要、封装、轨道编码及参数、时长、关键事件和预期输出。宿主侧以同一输入分别测自动、仅软解和适用的仅硬解模式。声明格式支持时附实际设备条件。

## 测量与通过条件

| 类型 | 验证方法与判定 |
|---|---|
| 状态与自动化 | 注入时钟和可控后端，覆盖取消、并发定位、切源时旧事件迟到、释放幂等；断言状态、事件顺序及唯一终止通知 |
| 声画与显示 | 用带同步标记的素材测实际输出偏差，记录暂停恢复、换轨和定位后的稳态偏差；真机核对颜色、裁剪、旋转及 Surface 重建 |
| 实时性 | 记录打开至首声/首帧时间、定位延迟、持续丢帧、CPU、内存和解码器名称；固定设备、样本、冷暖启动条件并统计 P50/P95 |
| 生命周期 | 快速切源、定位时退出、输入阻塞时释放、硬解资源耗尽及两个实例并播；验证无死锁，旧回调不污染新会话 |
| 资源与耐久 | 反复创建释放并长时间播放，记录 FD、线程、native 内存与解码器占用；检查稳定水位和退出后的资源回收 |
| 打包与接入 | 按三种渠道构建独立 release 宿主；检查混淆、ABI、16 KB 页加载、仓库元数据及制品摘要 |
| 发布 | 分列源码检查、构建、自动化测试、真机验收和发布状态。各项关联具体版本、设备、样本及证据路径 |

## 开工前需定案

最低 API 与出货 ABI 由设备清单确定；首版格式以产品必须播放的实际样本排序；通过同一组基准样本建立首帧、定位、同步与内存预算后固定门槛。发行方确定 Maven 命名空间和仓库地址。上述决策均应保留日期、负责人和依据。本规划不预填未经测量的性能结果。
