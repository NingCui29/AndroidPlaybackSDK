# 实际播放器 Demo 构建与真机实测指南

本指南详细记录了 **Android Playback SDK** 独立全功能播放器演示工程（`:demo` 模块）的架构设计、核心功能实现、真机交互验证与实测性能数据。

---

## 1. 模块定位与工程架构

播放器 Demo 旨在为业务开发团队提供一个开箱即用、具备生产级生命周期管理与实时性能诊断的官方示范参考。

### 1.1 工程结构

```
AndroidPlaybackSDK/
├── sdk/                               # 核心播放器 SDK 源码模块
├── demo/                              # 全功能交互式播放器演示应用模块
│   ├── build.gradle                   # 依赖与编译配置（纯原生依赖，零第三方冗余）
│   └── src/main/
│       ├── AndroidManifest.xml        # 应用清单、权限（存储与唤醒锁）及主 Activity
│       ├── java/com/cn/media/playback/demo/

│       └── res/
│           ├── layout/
│           │   └── activity_demo.xml  # 全屏 SurfaceView、悬浮 HUD、顶部与底部自适应控制栏

```

### 1.2 零依赖与纯净体积

Demo 模块直接依赖项目内置的 `:sdk`，不引入任何重型外部三方库，保障体积纯粹与极致启动效率：
- **编译产物大小**：Debug APK 仅约 `7.2 MB`（包含完整 64 位原生解复用器、音频处理器与软解动态链接库及调试符号表）。
- **运行环境**：Android 12 (API 32+)，ARM64-v8a 架构。

## 2. 核心功能与交互特性

### 2.1 生产级 Surface 生命周期协同
- **直接硬件渲染**：采用 `SurfaceView`，直连硬件合成器（Hardware Overlay），消除系统合成开销。
- **严格生命周期解绑契约**：在 `SurfaceHolder.Callback#surfaceDestroyed` 回调返回 Android 系统之前，同步调用 `player.detachVideoSurface(holder.getSurface())`，严格等待所有在途硬件与软件绘制缓冲归还，彻底杜绝帧泄漏与跨生命周期死锁。

### 2.2 极速关键帧定位（FastSeek）与精准定位动态切换
- **FastSeek（极速关键帧模式）**：
  - 底层基于 `MediaCodec.flush()` + `AudioTrack.flush()` 低延迟管道复用，避免重新创建编解码器组件。
  - 直接就近跳转至邻近关键帧出图出声，实测平均仅需 **5 ~ 55 毫秒**，实现如丝般顺滑的进度条拖动与步进预览。
- **ExactSeek（精准逐帧模式）**：
  - 严格预滚解码至目标精确时间戳，保障精确帧画面落点。
- **动态无缝切换**：用户可在界面上一键切换 `FastSeek:开` / `FastSeek:关`，播放器自动保持当前进度无缝热重载。

### 2.3 解码模式实时热切换
支持在播放过程中一键无缝轮询切换解码模式，且保持当前时间进度无缝接续播放：
1. **AUTO（推荐）**：平台硬件加速解码优先；若遇不支持的规格或硬件故障，自动平滑降级至软解。
2. **纯软件解码（SOFTWARE_ONLY）**：全程使用内嵌 FFmpeg 进行高性能 CPU 多线程软解与色彩矩阵映射。
3. **纯硬件解码（HARDWARE_ONLY）**：仅允许平台底层硬件解码直出，杜绝隐式回退。

### 2.4 实时高精度诊断 HUD（悬浮监控面板）
Demo 内置高对比度、半透明深色悬浮监控面板，支持一键显示/隐藏，实时以 200ms 高频周期呈现以下核心诊断指标：
- **播放生命周期状态**：实时展示 `PLAYING`、`PAUSED`、`READY`、`PREPARING`、`IDLE`、`ENDED`。
- **画面分辨率与编码规格**：如 `1920x1080 (h264)`。
- **解码后端类型**：清晰标明 `平台硬件解码 (MediaCodec Direct)` 或 `FFmpeg 软件解码`。
- **渲染吞吐与丢帧统计**：已渲染帧数、丢弃帧数及实时丢帧率（硬件直出下长期稳定为 `0.00%`）。
- **音频消费计数**：AudioTrack 声卡实际已消费输出的 PCM 采样帧累计总数。
- **定位耗时（Seek Latency）**：显示上一次 Seek 操作的真实端到端毫秒延时（如 `5 ms (FastSeek)`）。
- **进程物理内存（PSS）**：实时读取 Android 操作系统分配的物理内存驻留集大小（MB）。

### 2.5 画面比例自适应与多比例切换控制
播放器支持精确识别原始视频像素宽高比（SAR）及显示宽高比（DAR），提供 10 种画面呈现模式：
1. **自适应（FIT）**：按视频内嵌物理比例完整居中显示，保持画面不畸变并留黑边（默认推荐）。
2. **拉伸铺满（STRETCH）**：无视原视频比例，画面完全铺满整个屏幕。
3. **裁剪填充（CROP）**：保持原比例放大居中充满屏幕，自动裁剪溢出边缘，消除黑边。
4. **经典横屏比例**：`16:9`、`4:3`、`21:9`（宽银幕电影）。
5. **主流竖屏比例**：`9:16`（抖音/快手短视频）、`3:4`（社交媒体竖构图）。
6. **方形构图与点对点**：`1:1`（方形画幅）、`原始尺寸（ORIGINAL）`（1:1 无缩放居中映射）。
- **动态感知**：当视频元数据解析完成（`onVideoSizeChanged`）或切换文件时，自动计算并以动画或平滑重绘刷新 Surface 尺寸。

### 2.6 本机媒体文件选择与双模文件浏览器
针对 Android 12+ 存储权限策略及客厅机顶盒/触控大屏的不同操作习惯，Demo 实现了两套互补的文件选择通道：
1. **系统标准 SAF 选择器（System DocumentPicker）**：
   - 基于 `Intent.ACTION_GET_CONTENT` 调用系统级 `DocumentsUI`，支持选择本机任何位置的媒体文件。
   - SDK 原生支持 `MediaSource.fromUri(uri)`，通过 `ContentResolver.openAssetFileDescriptor` 高性能流式直通 Native 解码管道，无需复制文件。
2. **内置极简存储浏览器（Built-in Storage Browser）**：
   - 专为大屏遥控器与快速调试设计，支持一键直达 `/sdcard/`、`/sdcard/Download/`、`/sdcard/Movies/`、`/sdcard/DCIM/` 等常用多媒体目录。
   - 自动过滤常见音视频扩展名（`.mp4`, `.mkv`, `.mov`, `.flv`, `.ts`, `.m2ts`, `.avi`, `.webm` 等），支持文件夹无级下钻与 `.. (返回上一级)` 导航，点击视频文件即刻无缝加载播放。

### 2.7 完整播放控制体验
- **手势与控制栏协同**：轻触屏幕任意区域唤起/隐藏控制栏；处于播放状态时，控制栏无操作 10 秒后自动沉浸隐藏。
- **基础控制**：播放/暂停、停止、重新播放。
- **时间跳转**：支持 `-10s` 步退、`+10s` 步进、拖动进度条精细化预览跳转。
- **音频控制**：线性音量滑动条调节（0% ~ 100%）、一键静音/取消静音。

## 5. 纯软解丢帧深度根因与硬件合成优化

### 5.1 根因定位分析
在目标真机（4K 3840x2160 物理屏幕）上开启纯软解（FFmpeg 软件解码）时，初始测试观察到丢帧现象（渲染 410 帧，丢弃 120 帧，丢帧率 22.64%）。

经底层链路深度跟踪排查，定位出四大级联瓶颈：
1. **4K CPU 软件插值缩放瓶颈（主因）**：
   - 底层 `video_output.c` 调用 `ANativeWindow_setBuffersGeometry(sink->window, 0, 0, WINDOW_FORMAT_RGBA_8888)` 时，传入 `(0, 0)` 迫使 Android 默认分配与物理屏幕等大的缓冲区（3840x2160）。
   - 导致 `rgba_renderer.c` 中的 `sws_scale` 在 CPU 上强制执行 1080p YUV420P 至 4K RGBA 的双线性插值放大运算，单帧像素内存吞吐高达 33.2 MB，每帧 CPU 渲染耗时高达 40~55 ms，超过 30fps 视频的 33.3 ms 预算。
   - 视频 PTS 逐渐落后于音频主时钟超过安全阈值（66.6 ms），触发 `PlaybackOutput.java` 中的 `lateVideo` 机制持续主动丢帧。
2. **多线程并发解码深度不足**：
   - `software_decoder.c` 限制最大线程数为 4，未充分利用目标真机 8 核处理器的并发能力，且未显式指定 `thread_type = FF_THREAD_FRAME | FF_THREAD_SLICE`。
3. **颜色转换滤波算法未针对 1:1 进行 NEON SIMD 极速优化**：
   - 默认采用通用 `SWS_BILINEAR` 滤波，未启用 `SWS_FAST_BILINEAR`。

### 5.2 专项优化实施方案
1. **硬件合成器（HWC）零拷贝缩放替代 CPU 缩放**：
   - 在 `video_output.c` 中新增 `compute_buffer_geometry` 算法，根据窗口物理宽高、视频宽高、SAR 与旋转角度，动态计算保持窗口长宽比且不超过视频物理分辨率的最佳图形缓冲区尺寸（例如 1080p 视频在 4K 屏幕上配置为 1920x1080 缓冲区）。
   - 将 1080p $\to$ 4K 的画面放大任务完全交由 Android 系统的 SurfaceFlinger / 硬件合成器（Hardware Composer）由专用显示硬件单元（DPU）完成，**CPU 缩放开销彻底归零**。
2. **1:1 直通 NEON SIMD 快速色彩空间转换**：
   - 当 Native 缓冲区尺寸与视频画面像素完全对齐（$k = 1.0$）时，`sws_scale` 自动进入 libswscale 的无缩放直通内核（Unscaled Converter），利用 ARM64 NEON 向量指令直接执行 YUV420P $\to$ RGBA 转换，单帧渲染耗时由 45 ms 骤降至 **2.5 ~ 3.5 ms**（提速超 10 倍）。
   - 启用 `SWS_FAST_BILINEAR` 编译标志进一步提升转换效率。
3. **8 核拓扑软件多线程并发提速**：
   - 在 `software_decoder.c` 中显式配置 `decoder->codec->thread_type = FF_THREAD_FRAME | FF_THREAD_SLICE;`，并将并发线程数优化为 `av_clip(av_cpu_count(), 1, 6)`，充分释放多核心计算性能。

### 5.3 优化后实测验证数据
在目标真机（Android 12, 8核处理器, 4K屏幕）上进行纯软解模式持续压测验证：
- **纯软解丢帧率**：由优化前的 **22.64%** 骤降至 **0.00%**。
- **连续渲染帧数**：连续稳定播放 **3767+ 帧**，丢帧数保持为 **0**。
- **定位响应**：纯软解模式下拖拽 Seek 耗时稳定在 **9 ms**（FastSeek）。
- **物理内存**：软解稳态 PSS 内存仅约 **116 MB**。
