# D01～D05　Android SDK 发行与接入验收手册

适用于[发行设计](03-distribution.md)中的本地 AAR、离线 Maven 与远程 Maven 三个渠道。以固定坐标、AAR SHA-256 和候选清单关联各阶段证据。[本地开发候选的实测记录](d01-local-delivery.md)包含制品、符号、元数据、独立源码重建和 API 23 静态检查。下列为各阶段验收标准；实际远端与正式发布需对应渠道单独取证。

| 任务 | 进入条件 | 可复核的出口 |
|---|---|---|
| D01 候选组装 | N01、A01 | 候选清单及可追溯到同一构建的制品 |
| D02 本地与离线接入 | D01、Q01 | 两种渠道的独立宿主构建、安装、播放记录 |
| D03 远程暂存验证 | D01、Q01，具备已授权的暂存仓库和坐标；三渠道结项需 D02 的实际结果 | 远程解析来源、三渠道摘要、最终安装包设备记录 |
| D04 候选审核 | Q02、Q03、Q04、D02、D03 | 带审核结论的候选清单、限制和复验记录 |
| D05 正式发布与回读 | D04 通过且取得用户对目标渠道及版本的发布授权 | 正式仓库读回的制品、独立宿主冒烟记录、发行结果 |

## D01　AAR 制品与 Maven 元数据

| 核查对象 | 操作 | 通过标准 |
|---|---|---|
| AAR | 核对公开类、Android 清单、最低 API、consumer R8 规则及各 ABI 的 JNI 库；列出新增权限与宿主合并结果 | 公开接口与 A01 一致；包中组件对应已声明功能，混淆宿主可找到 JNI 入口 |
| Native 库 | 每个 ABI 清点 ELF 架构、SONAME、动态依赖、最低系统兼容性、页对齐和 Build ID；区分平台库与随包库 | 无缺失依赖；符号归档与发行二进制逐项匹配；与宿主其他 native 库的同名冲突有测试记录 |
| POM | 登记 groupId、artifactId、固定版本、aar 包类型、编译与运行依赖及作用域。按目标仓库核对项目、许可证、源码仓库及签名等要求 | 消费端能获得正确依赖；无本机路径、内部快照或凭据；仓库要求的附件齐全 |
| Gradle Module Metadata | 检查 release 变体、属性、公开与运行时依赖、引用的文件名、大小和校验值；与 POM 逐项解释差异 | 标准 Gradle 消费者能选中正确变体；仅使用 POM 元数据的独立验证也能解析约定依赖 |
| 随附材料 | 记录源码版本、工具链、FFmpeg 配置及补丁、许可证与对应源码获取方式、接入文档、支持矩阵及已知问题 | 能从任一 native Build ID 找到匹配符号和来源；须交付的资料均对应此版本 |

**验收顺序**：先生成一份 release AAR，再从同一构建导出元数据与附件；按相对文件名登记 SHA-256，保存独立候选清单。三个渠道使用同一份 AAR。POM、模块元数据、文档包、签名等分别核对各自清单值。原始 AAR 的摘要与宿主 APK 的摘要分栏记录。

## D02　本地 AAR 和离线 Maven

1. **隔离消费者环境。** 使用独立空白宿主及一次性依赖缓存，移除工程替代依赖、本地源码模块和其他 SDK 仓库。先预置且登记 JDK、Gradle、Android SDK、构建插件和宿主通用依赖，再断网。保存这些预置项，便于确认离线包自身提供了哪些依赖。无需清理开发者全局缓存。
2. **直接导入 AAR。** 仅按随包文档引入 AAR 及其明确列出的外部运行时依赖。裸 AAR 不替接入方解析 POM。Java/Kotlin 调用公开 API，构建启用 R8 的 release 宿主，检查清单合并和 APK 内目标 ABI，安装后执行冒烟。
3. **离线仓库按坐标接入。** 将仓库包解压到新目录，仅从文件型仓库解析 SDK 的固定坐标和所需依赖；保留解析图与实际文件来源。验证新目录、新缓存下断网可重复构建。隔离副本中移除目标 AAR，验证构建按预期报告无法解析，以排除命中旁路缓存。
4. **设备冒烟。** 各渠道至少播放 V01（有声视频）和 A01（纯音频、无 Surface），检查实际解码器、首声或可见帧、暂停恢复、定位及释放。登记渠道、宿主语言、工具链、设备固件、依赖图、AAR 摘要和安装结果。若仅有构建记录，设备栏保持未执行。

## D03　远程暂存仓库与最终安装包

1. 后续获得暂存验证授权时，登记暂存仓库、固定坐标、读写角色及可访问范围。使用独立消费者只读身份验证；分别记录未授权、制品不存在和元数据错误。日志保留来源仓库与响应类别，屏蔽凭据。
2. 从没有该 SDK 缓存的环境解析坐标，禁止同坐标回退到本地仓库。核对远程 AAR 与 D01、D02 的摘要及依赖闭包。分别复验常规 Gradle 元数据路径与 POM 路径；记录最终选中的版本及变体。
3. 用 Java 和 Kotlin 独立宿主覆盖启用 R8 的 release 构建，分别保存 APK 和从 AAB 生成并实际安装的拆分包清单。核对安装集包含该设备 ABI 的所有 native 依赖；检查 ELF 与最终安装包的页对齐。按 B01 在 D01 真机和 D06 的 16 KB 页环境记录实际加载与播放结果。
4. 回填三渠道对照表。远程可下载、依赖可解析、宿主可构建和设备可播放分别判定。暂存仓库验收结果不能填写到正式发布栏。

## D04　发行候选审核

对候选清单逐项汇总源码与 API 差异、构建、自动化、Q02 格式覆盖、Q03 异常并发、Q04 性能与回收、D02/D03 接入结果。每条证据注明实际验证版本、设备、样本及缺陷编号。给出“通过／待补证／需修复”及依据；没有真机覆盖的能力保留在限制清单。审核结论只针对登记的候选摘要。

| 候选变化 | 需要复验的范围 |
|---|---|
| AAR、JNI 或运行时依赖改变 | 更新清单，重验三渠道解析、宿主安装和受影响的格式、设备、稳定性与性能项；原结果保留为上一候选记录 |
| POM 或模块元数据改变，AAR 不变 | 复验离线与远程解析、依赖图及受影响宿主；若依赖图变化，追加运行时验证 |
| 仅安装说明或许可证附件改变 | 核对附件摘要，按改动复验接入操作或许可材料；保留 AAR 摘要与既有设备记录的关联 |

审核单应列明候选版本、各文件摘要、适用设备和 ABI、未决项、结论、审核人和日期。发现缺少必测证据时登记补验范围，待补项不得计为通过。

## D05　正式发布与发布后回读

1. **发布前核对。** 核对用户授权的仓库、坐标、版本和渠道，确认它们与审核单一致。检查目标坐标占用状态；若已经存在，先只读核对文件清单与摘要。不同内容占用同一版本时保留原版本，另行处理版本号。
2. **发布已审核制品。** 在获授权的渠道使用仓库支持的暂存提升或发布流程，复用 D04 的固定二进制。记录时间、目标仓库、事务标识、制品清单及状态。若上传或提升中断，先查看仓库可见文件和事务结果，再决定能否安全续传，避免重复创建或覆盖。
3. **从消费者入口回读。** 使用全新消费者缓存和正式仓库的只读入口，读取 AAR、POM、模块元数据及该渠道所需附件。逐项对比 D04 清单，核验适用签名；不能只读取发布端的本地副本。记录可见时间，索引或镜像传播期间单列“待可见”。
4. **用读回版本冒烟。** 从正式坐标构建独立 release 宿主并实际安装，按 D02 的 V01/A01 流程验证，保存依赖来源、制品摘要和设备证据。本地或离线渠道若在授权范围内，则回读实际交付归档并核对同一清单。
5. **关闭或处置异常。** 只有正式制品可取、身份和内容一致、冒烟通过后才登记发布验收完成。摘要不符、缺少依赖或运行失败时分别登记“已发布、回读异常”及受影响范围，保留证据和可回退版本。需要对外公告、修改仓库或发布修复版时另按授权执行。

## 发行参数与执行前登记

已确认的坐标、交付物、验收组数、审核条件和回读窗口见[D01～D05 决策记录](19-decisions.md)。私库 30 分钟窗口仅用于判断可见性；正式接受还需完成摘要比对、宿主构建和设备冒烟。候选重新构建后须更新清单并按变更范围复验。

| 阶段 | 执行前登记项 |
|---|---|
| D01 | 发行方命名空间、artifactId、版本规则、ABI/minSdk、外部依赖、符号与附件分发范围 |
| D02 | Java/Kotlin 宿主及工具链版本、离线预置项、离线仓库包含的依赖范围与分发许可 |
| D03 | 暂存仓库类型、端点、可用只读身份、测试坐标、宿主与设备覆盖矩阵 |
| D04 | 必测项和门槛、阻断缺陷口径、审核责任人、缺陷复验及批准记录 |
| D05 | 正式仓库及渠道、具体授权版本、提升方式、回读入口、传播等待预算、可回退版本 |

首版私库坐标已定为 com.cn.media:android-playback-sdk:1.0.0；实际仓库、权限引用及测试结果仍待登记。记录时分别标明设计审阅、制品检查、宿主构建、自动化、真机验收和正式发布状态。
