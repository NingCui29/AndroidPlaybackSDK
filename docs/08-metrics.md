# B03 验收指标表

已确认的产品范围为正式 AAR 仅 arm64-v8a、B02 全组必播、H.264 1080p30 单路实时。除 Q01 对应 K01～K04、K08 及 H04/L01/L02 对应 K10 和 Q02～Q04 七项已确认条目外，测次与其他数值门槛仍为建议。逐轮实测见[实施记录](21-implementation.md)。D01 为默认参考真机。候选样本见[B02 矩阵](07-samples.md)，设备角色见[B01 清单](06-devices.md)。将各模式、设备、固件及冷暖条件分组统计，避免合并掩盖慢路径。

|---|---|---|---|
| K01 视频启动延迟 | D01 × V01 | 有效 Surface 上 open 至首帧提交，单调时钟 ms；设备显示延迟另用首个可见帧测量 | 默认自启，进程冷启动与同实例重新打开各 30 次，报 P50/P95；D01 冷/暖 P95 ≤1000/600 ms |

## 第一批基线的执行与判定

| 指标 | 可直接执行的判定步骤 | 尚待冻结的门槛 |
|---|---|---|
| K01/K02 起播 | 记录请求、首帧提交或已消费 PCM 及外部可见/可听时刻；冷暖分别统计。失败或超时单列。 | P95 见 K01/K02；单轮未完成记录超时 |
| K03/K04 定位与同步 | K03 用画面帧号或声音标记比对目标，定位耗时和落点误差分别判定；K04 在同一外部时间轴计有符号偏差，校准采集延迟。 | 按 K03/K04，外部采集校准残差 ≤10 ms |
| K05 实时主项 | D01 上以正常速度、单实例播放 V01，锁定 1920×1080、30 fps、8-bit SDR；登记码率、profile、样本摘要、实际后端及显示刷新率。按每轮有效播放区间统计应显示帧、迟到丢帧、最长卡顿和媒体进度/墙钟耗时。用户暂停、定位区间剔除并登记；稳态卡顿保留。 | **已确认，D01/V01 自动模式**：每轮 10 分钟、3 轮；进度/墙钟 0.99～1.01、迟到丢帧率 ≤1%、最长卡顿 ≤200 ms。实际显示以帧号采集验证；只报平均帧率不足以判定。自动模式作为产品路径，强制软解、仅硬解分别记录。 |
| K06/K07 负载与耐久 | 按轮保存温度、实际后端、CPU、PSS、native heap 及漂移曲线；长播区分循环边界与运行中断。 | 观察窗口及相对增长预算按 Q04；D01 绝对 CPU 上限待定；HEVC 只登记实测表现，其实时目标待确认 |
| K08/K10 释放与恢复 | stop 到 Idle 与 release 到完成通知分别计时；正常与停供分组。换轨、重绑、回退同时记录逻辑完成及实际声画恢复，核对旧会话输出数。 | stop、release 按已确认 K08；硬转软时限见 K10；路由与 Surface 恢复时限按已确认 L01/L02 分组判定；回收后空闲水位按 Q04 |
| K09 格式功能 | 分母包括 V01～V11、A01～A06 所有已确认子编号，逐个执行打开、输出、暂停恢复、可定位输入前后定位及自然结束。X01/X02 另列边界用例。HEVC 功能计入必测。 | 每一必播组合必须有匹配预期的真机结果；未测或失败不能计为通过。样本见 B02 |
| K11 发行兼容 | 核对正式 AAR 的 native ABI 集合恰为 arm64-v8a；在 D01 真机、arm64 16 KB 页环境分别安装、加载、播放。x86_64 模拟器结果仅作开发证据。 | 具体设备/镜像、固件与 APK/AAB 安装记录待补；所有必测组合通过后方可结项 |

先登记 D01 实机及素材摘要，再用同一构建试测；评审数值后冻结门槛，最后执行正式验收。未指定机型时可完成用例设计，不能据此判定性能已达标。

K01～K04 用于 Q01 的已确认门槛、测次及采集精度见[本批集中确认单](19-decisions.md)。真机为 RK3588 NEXBoard，样本按 B02 摘要登记。各项执行状态以对应原始测量为准。
