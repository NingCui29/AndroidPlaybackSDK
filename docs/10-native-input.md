# N01、I01～I03 构建与输入层设计评审

**交付边界**为独立 Android 播放 SDK 的 native 库、只读输入适配器，以及交给下游解码器的压缩包。验收可以在不启动音视频解码器的情况下完成：用独立宿主加载库、逐字节比对输入、记录轨道与包序列，并在指定阻塞点发起取消。本文给出的均为预期行为。

| 任务 | 前置任务 | 可独立交付的结果 |
|---|---|---|
| N01 | B01、B02 | 每个目标 ABI 的 FFmpeg、JNI 桥及可追溯构建清单 |
| I01 | A01、N01 | 文件、URI、FD 区间统一为带能力说明的只读字节源 |
| I02 | I01、A02 | 顺序源的等待、终止与资源回收协议 |
| I03 | I01、N01 | 媒体信息、选轨结果、分轨压缩包及终止信号；顺序输入联验还需 I02 |

## N01　FFmpeg 与 JNI 构建

1. **冻结输入。** 从 B02 的每项必测素材反查所需 demuxer、parser、decoder 和码流转换组件，标明“哪份样本需要它”。保留 libavutil、libavformat、libavcodec、libswresample、libswscale 及实际依赖。文件和 URI 统一走自定义 AVIO；对还会请求第二个资源的封装，首版限定只访问宿主交付的输入。编码器、CLI 和网络协议按首版范围裁剪。
2. **按 ABI 独立构建。** 每个 ABI 单独记录源码版本及摘要、补丁顺序、工具链、最低 API、配置参数、启用组件和依赖。JNI 桥仅向 SDK 暴露会话及输入操作；跨库对象由约定的所有者释放。产出供打包的动态库、配套符号和 Build ID。配置变化应能定位到受影响的样本与 ABI。
3. **检查实际二进制。** 对每个 ABI 检查 ELF 架构、SONAME、所需动态库和未解析的外部符号；区分平台提供项和必须随 AAR 打包的项。对照构建配置保留许可声明、补丁和对应源码获取信息。AAR 跨渠道一致性在 D01～D04 验证。[发行设计](03-distribution.md)

| 验收项 | 操作与通过标准 |
|---|---|
| N01-1 重建 | 从记录的干净构建环境重建；目标 ABI、组件列表和依赖闭包一致。记录二进制摘要；摘要不一致时记录差异来源 |
| N01-2 加载 | 独立宿主在每个目标 ABI 实际加载 JNI 桥，报告 FFmpeg 运行时版本与构建标识；D01 真机与 16 KB 页环境单独留证 |
| N01-3 裁剪与追溯 | 对照 B02 逐行确认必需组件存在；以任一产出的 Build ID 取回准确源码、配置及符号。记录与另一 native SDK 同宿主时的加载结果 |

## I01　文件、URI 与描述符区间

输入对象持有 SDK 自己的描述符、逻辑起点、可选长度、当前逻辑位置及取消状态。文件路径以只读方式打开。content URI 由 ContentResolver 在工作线程打开，保留提供方返回的偏移和声明长度；禁止通过猜测真实路径绕过提供方。宿主直接传 FD 时在接受请求前复制，复制或参数检查失败时旧媒体继续有效。[Android AssetFileDescriptor](https://developer.android.com/reference/android/content/res/AssetFileDescriptor)

| 边界 | 处理规则 |
|---|---|
| 已知区间 | 使用 64 位字节位置。逻辑零对应物理起点；检查起点、长度及相加溢出。每次读取限于剩余区间；恰在结尾返回 EOF。已知物理大小且区间越界时拒绝输入 |
| 未知长度 | 与零长度分别表达；仅在源能给出可靠大小时提供长度。禁止猜测结束位置；空区间读到 EOF，媒体探测可报告无有效内容 |
| 可定位文件 | 使用独立逻辑游标和按位置读取，避免复制 FD 后共享文件偏移干扰宿主；定位区间外返回明确错误，失败不移动游标 |
| 顺序 FD | 首版只接收从当前流位置起、逻辑偏移为零的输入；有界长度仍生效。非零起点无法安全定位时返回能力错误。交接后宿主停止并发读取 |
| 关闭与错误 | 只关闭已取得的副本或 SDK 打开的资源。区分权限拒绝、提供方打开失败、非法区间与读取失败；诊断遵循 A03 脱敏约定 |

**I01 验收。** 用 X01 将同一 V01 分别经路径、URI、带前后哨兵字节的 FD 区间读取，比对有效字节数和摘要；单独测试区间首尾、越界定位、未知长度、空区间及整数溢出。接收后立即关闭宿主 FD，仍能读完；宿主保留普通文件 FD 时其游标不因 SDK 读取改变。无权限 URI 和复制失败各验证一次错误归属与 FD 回收。

## I02　顺序读取、取消与关闭

对顺序输入分别报告“不可字节定位”和“长度是否已知”。暂时无数据保持等待；自然结束、故障和主动取消分别传回。小块或短读只消费实际取得的字节。顺序源可以读成员头部已足够描述轨道的媒体；遇到必须回读的封装时给出输入能力错误。

| 阻塞位置 | 取消设计 | 验收注入点 |
|---|---|---|
| URI 正在打开 | 使用支持取消的提供方接口传递请求，取消与返回 FD 竞态时立即回收迟到的 FD | 提供方延迟返回，发起切源；旧请求只终结一次，迟到结果不附着到新源 |
| 管道等待数据 | 输入工作线程同时等待数据就绪和独立取消信号；就绪后采用不会无限阻塞的读策略。确认由 SDK 控制读取方式，避免更改共享 FD 标志影响宿主 | 写端保持打开但停供；分别执行 stop、release，记录等待被唤醒、线程退出和 FD 回收时间 |
| FFmpeg 正在探测或读取 | 会话取消标记同时供 FFmpeg 中断回调和自定义 AVIO 检查；AVIO 自身的等待必须可唤醒 | 首包未到、探测到一半和媒体中途分别取消；结果为取消或被取代，不能生成自然播放结束事件 |
| 包队列已满 | 取消时广播唤醒生产者和消费者，检查会话编号后退出 | 暂停消费者并填满队列，再取消；线程均可退出，不持队列锁等待线程结束 |

先标记取消、唤醒等待，再等待拥有输入的线程退出，最后释放格式上下文、AVIO 和描述符。避免靠其他线程强关 FD 来打断未知系统调用。若提供方无视取消，丢弃旧事件并不等于资源已释放；该类提供方的支持范围和超时处置须单独确认。release 完成通知只能在资源退出后发出。[FFmpeg 中断回调](https://ffmpeg.org/doxygen/trunk/structAVIOInterruptCB.html)

**I02 验收。** 另测停供后恢复、写端正常关闭、定位请求被拒后继续顺序播放、连续两次 release。阻塞释放对照 K08 的 P95 和最大超时，报告超时次数、线程及 FD 余量。stop 单独测量，不以 release 的通过记录代替；门槛未冻结时只登记数据。

## I03　格式探测、选轨与分包

1. **探测。** 读取线程独占格式上下文，将字节源接入 AVIO，按内容识别封装并取得轨道信息。设置探测字节、媒体分析时长及独立的墙钟截止时间；媒体时间预算不能限制停供等待。顺序输入允许复用有限的已读前缀。记录终止原因，区分数据损坏、缺少组件、预算耗尽和需要回读。[FFmpeg 解封装接口](https://ffmpeg.org/doxygen/trunk/group__lavf__decoding.html)
2. **建立媒体快照。** 登记轨道索引与会话内 ID、类型、编码、初始化数据、时间基、语言、默认标记、视频尺寸与音频参数。时长和时间戳缺失均以“未知”保留。封面图从正常视频候选中排除。按宿主指定、默认标记、可支持候选的顺序选轨；指定轨不存在时回报选轨错误。输入可按字节定位只是条件之一，对外还需结合封装与时间索引能力决定是否开放媒体定位。
3. **交付压缩包。** 按读取顺序分发所选流，保留原始 PTS、DTS、时长、时间基、关键帧标记及必要边带数据；不得按 PTS 重排带 B 帧的输入。队列项带会话编号和时间轴版本，通过引用交接所有权。未选轨、旧版本和入队失败的包及时释放。
4. **背压与终止。** 分别限制音视频队列累计字节、包数和可估算媒体时长；未知时长时仍执行前两项硬限额。队满等待低水位或取消；单包大于硬上限时返回资源限制错误，避免永远等不到空间。视频输出解绑且音频继续时，停止向暂停消费的视频队列积压，恢复遵循关键帧策略。自然 EOF 为每条选中轨交付一次排空信号；异常和取消保留独立结果，下游排空后由会话判定 Ended。

| 验收项 | 样本和检查方法 | 通过标准 |
|---|---|---|
| I03-1 探测与选轨 | V05、V11、A01、A06，对照 B02 已登记轨道 | 双音轨 ID 独立；纯视频没有音轨，带封面音频没有可播放视频轨；未知时长未被写成零 |
| I03-2 分包正确性 | V01、V04、V11；以独立参考包清单比较指定轨的包顺序、时间基、时间戳及关键帧 | 比较在同一解封装边界进行，允许缺失时间戳；B 帧样本保持解码顺序，未选轨不入队 |
| I03-3 故障与预算 | X02、慢速 X01、超大单包、刻意缩小预算 | 诊断给出实际消耗与终止阶段；队列水位不越硬上限；取消可退出满队列等待 |
| I03-4 结束与隔离 | 正常尾部、截断输入和切源后迟到的包 | 正常 EOF 各轨一次；截断按样本预期处理；新会话不接收旧包，引用在退出后回收 |

具体数值集中维护在[参数确认单](19-decisions.md)。五项参数已于 2026-11-11 确认。

- **I01**：用稀疏文件验证跨 2 GiB/4 GiB 读取，另测区间加法溢出、逻辑结尾和宿主关闭原 FD。复制描述符不隔离共享文件状态；顺序源由 SDK 独占读取，禁止修改会影响宿主的共享状态。
- **I02**：打开计时从向提供方发起请求开始；成功取得输入后另起探测计时。探测期先到的墙钟截止优先，播放期停供计时以最近一次成功读入数据为起点。超时与用户取消分别结束请求；超时后提供方仍可能持有工作线程，单独追踪迟到结果和真实回收耗时。正常与停供两组按 K08 分别统计。
- **I03**：探测字节按实际从源取得的字节累计，前缀回放不重复计；媒体分析时长与墙钟各自记录。探测信息不足且预算触顶时不能按“编码不支持”归因。轨道降级沿用 A03 已确认策略。
- **包队列**：容量按压缩包有效数据和边带数据计，时长按可估算的有效媒体时长；时间戳缺失时仍执行字节和包数上限。入队前检查剩余容量，超大单包直接返回 RESOURCE_EXHAUSTED；合法包在空队列须可取得进展（单包时长超过时长水位时只单独入队并暂停后续生产）。前缀缓存、FFmpeg 内部分配及解码帧单独记账，队列预算不能视为播放器总内存上限。
- **验证**：对每项字节/包数边界测试等于上限和超过上限，用慢速 X01 覆盖截止前恢复与截止后返回、满队列取消及资源回收。首轮 V/A 必播样本若触顶，记录设备、样本、实际水位再评审预算。
