# L01～L02　播放中切换音轨、输出设备和 Surface

评审稿。L01 依赖 S04/S05，L02 依赖 H03/S05。保持原播放会话，分别记录选中音轨、实际音频路由、视频后端、输出绑定版本和用户播放意图。同一控制队列串行决定切换结果，耗时的准备和资源清理由各后端线程执行。真机步骤见[生命周期验收表](16-lifecycle-device.md)。

## L01　音轨切换

| 时点 | 设计决策 | 宿主可观察结果 |
|---|---|---|
| 接收请求 | 校验媒体会话和轨道 ID。切到当前轨按幂等成功处理；不存在、跨媒体或不可解码的轨道直接失败 | 快照区分当前轨与正在准备的目标轨；失败保留原轨 |
| 准备新轨 | 探测新轨采样率、布局、编码与首个可用 PTS，准备解码和重采样。可定位源从切换位置预滚；若解封装游标共用，应协调视频与音频的定位或使用独立读游标，避免单独移动主游标破坏正在播放的视频 | 原轨可用时继续播放。准备耗时过长时重新读取媒体时钟，防止按过期的位置切换 |
| 提交切换 | 在确定的媒体时间边界结束旧 PCM 写入，使旧音频队列版本失效。按输出端能力停止或清理未消费旧 PCM；新轨跨越边界的 PCM 按样本裁切。兼容时复用 AudioTrack，配置改变时更换输出并重新建钟 | 原子更新选中轨、时钟锚点和请求结果；首个新轨样本被消费另发诊断。记录已进入物理输出链的旧音频尾部 |
| 失败与回滚 | 提交前失败时丢弃新轨资源；提交之后失败时，仅在原轨能按当前位置重新准备并成功输出时报告已恢复。两轨都不可用时公开当前无活动音轨及原因 | 快照中的活动轨始终反映实际结果；保留目标轨错误和回滚结果 |
| 顺序输入 | 从当前位置开始接收新轨数据，等待可解码包并对齐当前时钟。无法回读已略过的包。超出缓存或等待预算时保留原轨，或明确报告切换失败后的活动状态 | 记录是否可定位、等包耗时及首个有效新轨位置 |

暂停时切换只更新选轨与准备状态，恢复后从保存位置出声。快速 A→B→A 时，每个已接收请求只有一个终止结果；旧轨版本不能继续写入新输出。实际听感以标记回录判定，不能把新轨选择事件时间当作旧声物理消失时间。

## L01　音频输出设备变化

1. 区分设备已连接、宿主偏好和 AudioTrack 实际使用的输出。接入耳机未必改变活跃路由。首版建议由系统和宿主决定路由策略，SDK 观察实际路由及写入错误。路由查询及监听按目标 API 使用可用接口；未播放或无法观测时记为未知。[Android AudioRouting](https://developer.android.com/reference/android/media/AudioRouting)
2. 若系统已平滑切到新路由，AudioTrack 有效且采样消费继续，更新实际路由记录，验证时钟连续后复用输出。若写入失败、实例失效或配置不兼容，冻结最后可信的已消费媒体位置，终止旧写入，释放失效输出，按新路由能力准备 PCM、重采样和 AudioTrack。
3. 从可信位置续播。可定位输入可预滚；顺序输入仅利用有界 PCM/包缓存，缺失区间单独计入中断。新实例的播放计数从新锚点解释，避免把计数归零当作媒体回到起点。蓝牙等路由的呈现延迟按实际输出另测。
4. 路由失败时按实际可用设备重新查询，禁止无界重建。保留音量、静音、选轨和暂停意图；宿主若因拔耳机要求暂停，以最新意图为准。旧路由无法恢复时如实返回实际路由或未知，并报告能否继续。

## L02　Surface 解绑与重建

Surface 属于宿主，SDK 拥有自己的输出引用。每次绑定分配版本。主动换屏时先请求解绑，收到完成通知再销毁旧输出。对系统触发的 SurfaceView 销毁，宿主适配层必须在 surfaceDestroyed 返回前确保绘制线程已停止访问旧 Surface：设置立即生效的写入屏障，并与在途绘制同步。异步完成通知本身无法满足这个时序。屏障不能依赖主线程回调才能解除。[SurfaceHolder.Callback](https://developer.android.com/reference/android/view/SurfaceHolder.Callback)

| 后端 | 解绑旧输出 | 绑定新输出与首帧 |
|---|---|---|
| FFmpeg 软解 | 禁止新版本不匹配的绘制任务进入；等待已经锁定窗口缓冲的操作完成并归还缓冲，释放 SDK 的 native window 引用 | 取得新窗口引用，重新读取尺寸、stride 和有效裁剪区。仅提交当前时间轴和绑定版本的帧；保留的帧须仍符合当前位置 |
| MediaCodec 硬解 | 停止向旧 Surface 提交 render；丢弃仍归客户端持有且有效的过时输出。已提交给合成器的帧无法撤回。旧 codec 被 flush/释放后禁止再用其索引 | 新旧 Surface 均有效且组件支持时可切换输出；新 Surface 尚未就绪或切换失败时停止旧实例，从可解码点重建。新实例重新配置 CSD、裁剪及旋转。自动和仅硬解继续遵循 H04 的后端策略。[MediaCodec 输出 Surface](https://developer.android.com/reference/android/media/MediaCodec#setOutputSurface(android.view.Surface)) |

**含音轨媒体**默认保持音频播放，解绑后视频队列不得堵塞音频。重新绑定时以当前音频位置恢复画面；若需回读关键帧，协调读游标并避免重复输出音频。顺序输入使用缓存或等下一可解码点，超过预算报告视频恢复失败及实际音频状态。

**纯视频**默认在输出丢失时冻结位置，区分“因无 Surface 暂停”和“用户主动暂停”。仅在先前有播放意图且期间未被撤销时恢复推进。恢复失败保留可用的媒体状态；stop、release 或切源使所有在途切换失效，迟到结果只能清理自有资源。

## 并发与已确认的切换参数

| 场景 | 确定性要求 | 参数范围 |
|---|---|---|
| 换轨期间路由变化 | 新轨提交前重新核对输出版本；路由回调不能把选轨回滚到旧值 | 预滚预算、旧声尾部容差、允许静音间隔、回滚等待时间 |
| 暂停或定位期间拔耳机 | 保存最后播放意图，输出从最新时间轴建钟 | 最低 API 监听策略、出货路由清单、是否由宿主要求暂停、路由中断与同步门槛 |
| 连续解绑、重绑或页面销毁 | 旧版本阻止新提交；记录最后在途操作与屏障耗时；释放完成前归还所有引用 | 屏障等待预算、超时诊断、重绑首帧门槛、缓存与关键帧等待上限 |
| 重建期间切源或释放 | 新源不接收旧事件；同一请求不重复完成 | K04/K08/K10 各设备阈值、资源回落容差、测试轮数 |

已确认的六项参数集中在[决策清单](19-decisions.md)。轨道提交、实际路由改变及有效新 Surface 到达分别作为计时起点。对齐事件时间与物理回录后统计旧声尾部和静音间隔；无有效采集时将对应结果记为未测。屏障性能超时只触发取证，不改变旧 Surface 的所有权和访问约束。
