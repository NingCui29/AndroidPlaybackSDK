# H01～H04　真机验收操作表

前置：完成 [Q01 软解闭环](12-softdecode-device.md)，取得同一版本或可追溯版本的软解参考录制。使用 [B01 设备](06-devices.md)、[B02 样本](07-samples.md)与[B03 指标](08-metrics.md)。已有部分真机结果，每个构建的覆盖以[实施记录](21-implementation.md)为准。

## 实机操作顺序

| 步骤 | 操作 | 判定与取证 |
|---|---|---|
| 1　建立对照 | D01 记录系统、SoC、固件、API、实际 ABI、输出路由、构建、素材摘要；适用时 D03 换平台重复。先用仅软解跑 V01、V03 | 保存实际 FFmpeg 后端、帧号和闪光/短音标记；确认设备采集的时间偏差 |
| 2　验证候选选择 | V01 和 V03 分别用自动、仅硬解播放；再选已确认不支持的组合，或在测试宿主制造空候选集 | 对齐枚举结果、硬件分类依据、实际组件名、配置结果和第一张可见画面；不支持时仅硬解明确失败，自动模式记录回退 |
| 3　验证码流适配 | 播 V01、V10（AVC 容器与流内参数），V03/V04（同 HEVC 轨重封装），V11（B 帧）。补登记 HEVC Annex B、参数集变化及截断变体 | 对照参考访问单元数量、CSD 类型、PTS、显示顺序和定位后首帧。截断样本产生带阶段的错误；早期 flush 后参数齐备、正常流无重复显式注入 |
| 4　验证 Surface 直出 | 用 V02 旋转标尺、已登记的动态尺寸变体，启动、暂停、定位、恢复、解绑再重绑 | 保存输出格式变化、首提交和外部首帧；核对裁剪和旋转。解绑完成后旧输出无新提交，重绑后提交到新目标 |
| 5　初始化失败 | 在独立测试宿主分别于创建、配置、启动阶段注入失败；每次用自动和仅硬解对照，结束后再开同一文件 | 自动模式可由软解呈现首帧；仅硬解保留原错。实际创建过的资源全部回收，失败组件不重复选择 |
| 6　可定位源运行中失败 | V01 播过一个 GOP 后，选两个关键帧之间的位置注入解码失败。再覆盖恢复中暂停、seek、切源和 release | 保存故障前时钟、预滚入口、实际恢复帧、音频标记和回退次数；按 K03/K04/K10 检查落点、同步和耗时。旧会话无迟到输出 |
| 7　顺序源运行中失败 | 用 X01 的可顺序解封装变体，经管道输入；分别准备缓存完整、缓存被淘汰但后续有关键帧、后续无可用入口三种条件 | 依次验证从缓存恢复、等下一入口恢复、到预算后终止；全程无回读。记录音频是否连续及视频恢复时的音画偏差 |
| 8　复核真实设备行为 | 在已知有约束的实机尝试真实不支持规格或并播资源争用；只在实际发生时登记对应故障，采集平台原始诊断 | 实机正常硬解、实机注入失败、实机原生故障分别标记。未触发原生故障登记“未复现”，保留注入结果的适用范围 |

## 记录与完成标准

候选 e271c519 的 V01 每 250 帧出现一个随机访问点。独占真机用例将可定位源的注入点放在 9.1 s，顺序源分别在 1.1 s、7.7 s、3.0 s 注入，覆盖完整缓存、缓存淘汰后遇到下一入口和等待超时。每种配置执行十轮，另外对照仅硬解模式。恢复计时取 `VideoRecoveryInfo.failureNanos` 至 `firstSoftwareSubmissionNanos`，位置误差取首次软解帧 PTS 减恢复目标。等待测试通知的耗时单独记录。无入口组在素材约 5 s 处停供，视频降级后恢复供数并核对新增音频消费。顺序源超时须保留原始硬件错误、视频轨降级和后续音频消费。新增组的真机结果待回读。[测试包溯源](../artifacts/validation/20261113-144238-timings/progress/h04/controlled-apk/provenance.json) · [真机队列](../artifacts/validation/20261113-144238-timings/progress/h04/queue.txt)
