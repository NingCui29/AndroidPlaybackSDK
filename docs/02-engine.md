# 播放内核详细设计

## 数据与线程

输入 → FFmpeg AVIO → libavformat → 所选轨道压缩包队列。视频队列进入 MediaCodec 或 libavcodec，再输出到 Surface。音频队列进入 libavcodec 和 libswresample，再交付 AudioTrack。控制线程独占状态转换；读取线程持有格式上下文；解码工作线程持有各自后端。耗时的音频写入不得阻塞控制线程。压缩包和帧按引用计数交接，异步使用期间保留引用。

输入层定义读取、可选定位、取消和关闭。文件区间采用相对起点与长度，边界检查同时处理未知长度和整数溢出。对共享文件偏移的复制描述符，普通文件优先使用定位读取；顺序源要求调用方交接后停止并发读取。对管道采用可唤醒的等待机制，保证 stop 能取消阻塞。探测设定字节和时间预算；要求回读而输入不可定位的封装返回明确错误。

包队列同时限制字节、累计时间及包数；解码帧单独按内存预算限制。避免视频输出丢失后视频队列填满，连带阻塞音频读取。封面图片作为元数据，排除在正常视频轨选择之外。

## 视频适配与回退

1. 从流参数取得 MIME、profile、level、位深、显示尺寸和初始化数据。对照设备候选解码器能力，再实际 configure、start 并观察首个输出。诊断记录实际 codec 名称；系统 MediaCodec 也可能选中软件实现，“仅硬解”要求有依据识别硬件实现，否则报告能力未确认。
2. 根据封装和后端准备 CSD（编解码器初始化数据）。H.264 处理 SPS/PPS，HEVC 处理 VPS/SPS/PPS。按后端要求转换长度前缀或起始码，保持包的解码顺序和独立显示时间戳。
3. 硬解直接输出到 Surface。对输出格式变化更新可见裁剪区、像素宽高比和旋转信息，明确由后端或宿主执行旋转，避免重复处理。软解基线使用 libswscale 转色和 native Surface 输出，按实际 stride 写入；色彩矩阵、范围及高位深输入降级须有样本验证。
4. 实例维护按会话、轨道、配置和后端记录的失败集合。初始化失败自动尝试软解；运行中失败时，先保存时钟位置、停止交付旧帧，再从可解码点预滚恢复。不可定位源依赖有界关键帧缓存或等待下一关键帧。超过配置等待预算后终止恢复。仅硬解或仅软解模式按调用方策略返回错误，不自行改变后端。
5. 多实例竞争由实际设备分配结果决定。不能取得硬解资源时按实例策略回退；记录资源不足与格式不支持的区别。软解落后时记录解码耗时、丢帧与队列水位，持续超出实时预算时通知宿主。

## 音画同步与切换

内部时间统一为微秒。解封装时保留轨道 time base 和起始偏移；负起始时间、缺少 PTS、B 帧和时间戳不连续均需单独验证。音频主时钟通过输出端已播放的采样帧和对应媒体时间计算，处理播放头回绕、暂停及输出设备重建。静音只调输出增益。无音频时使用单调时钟并扣除暂停时间。提前的视频帧按时提交，过期帧根据容忍窗口丢弃。阈值通过参考设备测量后确定。

定位顺序为冻结旧时钟、递增时间轴版本、取消旧包和输出、让读取线程定位到目标前关键帧、清理解码与音频缓冲、预滚并丢弃目标前输出、建立新时钟、恢复最后的播放意图。长 GOP 素材的预滚耗时单独记录。换轨时用当前位置对齐新音轨并重置音频锚点，避免旧 PCM 残留。

Surface 丢失时先同步解绑旧输出。带音轨内容默认继续音频，重新绑定后恢复当前时间点的视频；纯视频默认暂停。对于从不可定位源恢复画面，需要缓存或等待关键帧。路由变化后核实实际输出；消费正常且配置兼容时复用 AudioTrack，失效或不兼容时重建并从已消费位置建钟。

## 结束与释放

输入 EOF 后排空解码器延迟帧，再等待有效视频交付和 AudioTrack 尾部 PCM 播放完成，最后报告 Ended。主动停止直接取消等待。释放依次关闭命令入口、使旧任务失效、唤醒输入及缓冲等待、等待工作线程退出、释放 codec 和输出引用、关闭格式上下文和描述符。每项资源由创建或接管它的对象释放；部分初始化失败同样走安全清理路径。
