# A01～A03 接口、状态与诊断评审表

本表细化[SDK 接入契约](01-sdk.md)。本表七项公开契约已于 2026-11-11 确认；A01 实施依赖 B01 定案，A02 依赖 A01，A03 依赖 A02。以下为设计预期，测试尚未执行。

## A01 调用和资源交接

| 场景 | 接入方动作 | SDK 承诺与验收观察点 |
|---|---|---|
| 文件描述符输入 | 传入描述符、非负偏移和可选长度 | 同步检查区间溢出并复制描述符；接收成功即可关闭原描述符。复制失败不接收请求，旧媒体仍可播放 |
| content URI | 授予读取权限后打开 | 异步打开失败时返回权限或读取错误；不能随机访问的输入在快照中声明不可定位 |
| 媒体准备 | 调用 open 后等待结果 | 成功时快照含媒体 ID、轨道、时长是否已知及可定位性。未知时长不显示成零；跨媒体使用旧轨道 ID 会被拒绝 |
| Surface 交接 | 绑定新输出或请求解绑 | 解绑完成表示旧引用已退出所有交付路径；解绑期间继续处理音频。宿主负责与平台销毁回调协调，已失效输出不得继续写入 |
| 播放意图 | 调用 play、pause、静音 | 准备和定位期间最后一次播放意图生效；静音保存原音量和媒体时钟 |
| 监听与快照 | Java 监听器或 Kotlin 调用方读取同一实例 | 公共时间统一为毫秒；默认主线程回调，允许指定串行执行器。先提交不可变快照，再交付与其版本对应的事件 |
| 实例终结 | stop 后复用，release 后等待完成 | 停止完成后可再打开；释放中的重复 release 共享同一完成结果。已释放实例拒绝新命令，不再分发媒体事件 |

评审时从 Java 与 Kotlin 两侧分别走查“打开 URI → 准备 → 播放 → 解绑 → 释放”和“纯音频打开 → 选轨 → 定位 → 停止”。各项取值见下方已确认契约。

## A02 状态转换与竞态验收

| 初始条件与命令顺序 | 预期最终状态 | 必须检查的事件或资源 |
|---|---|---|
| Idle → open → play → pause，随后准备成功 | Ready，播放意图为暂停 | open 成功一次，不启动输出；play/pause 结果表示意图已接受 |
| Playing → seek A → seek B，A 仍在预滚 | Playing，位置落在 B 的有效落点 | A 已接受且未完成时收到被取代结果；只有 B 的时间轴可继续交付 |
| Playing → seek → pause | Paused | 定位完成携带实际落点，随后不自动开播 |
| Preparing 旧源 → open 新源 → 旧源迟到失败 | 由新源决定 | 已接收的旧请求仍有终止结果；旧媒体错误不能覆盖新源快照 |
| Playing → 选择不存在的音轨 | Playing，原轨继续 | 仅选轨请求失败，不进入会话 Error |
| Playing → 文件读尽 → 输出排空 | Ended | 最后音频实际消费且视频完成交付后才发结束事件 |
| Preparing → stop，读取阻塞 | Idle | 先取消输入并唤醒等待，再完成 stop；可重新打开 |
| 正在定位 → release → 再次 release | Released | 最终通知前结清已接收请求，工作线程退出；仅一次资源清理 |
| Error → open 有效源 | Ready 或按新意图播放 | 清除旧错误，分配新会话编号，旧回调不更新新状态 |

排序规则：接收顺序由同一实例的控制队列确定。请求编号跟踪单条命令，会话编号隔离切源，时间轴版本隔离定位。命令结果、状态变化和首帧事件分别可观测。自动化验收用可控后端故意延迟、重排旧事件；真机补验阻塞取消、Surface 解绑和尾音结束。释放耗时采用[B03 指标 K08](08-metrics.md)。

## A03 错误、恢复和证据

| 错误类别 | 触发条件 | 默认处理 / 验收 |
|---|---|---|
| INPUT_PERMISSION / INPUT_IO | URI 无权读取、源不可读 | 打开失败并报告具体阶段；重新取得授权后允许再次打开 |
| SEEK_UNAVAILABLE | 对顺序输入定位 | 当前播放保持，只有定位请求失败 |
| FORMAT_UNSUPPORTED / TRACK_UNSUPPORTED | 封装无法探测，或选定轨道无可用解码器 | 区分容器和轨道；若仍有可播轨，按已确认的轨道降级策略处理 |
| DECODER_INIT / DECODER_RUNTIME | 后端启动失败或输出中断 | 自动策略允许有界回退并报告前后后端；仅硬解模式保留失败原因 |
| RESOURCE_EXHAUSTED | 第二实例分配 codec 或内存失败 | 记录设备及失败阶段，第一实例继续播放；第二实例按策略恢复或失败 |
| OUTPUT_LOST | 无效 Surface 或 AudioTrack 失效 | 记录输出类别，按媒体类型恢复；恢复成功后更新输出状态 |
| CANCELLED / SUPERSEDED | stop、切源或新定位取代旧请求 | 记录操作终止结果，无会话故障告警 |

诊断记录关联构建版本、会话编号、请求编号、时间轴版本、阶段、轨道类型、真实后端、稳定错误类别和经脱敏的后端原始原因。验收使用含绝对路径、URI 凭据和查询令牌的测试输入，检查消息、原始异常和导出记录均不泄漏测试值。恢复成功应保留首次失败及恢复耗时，供区分“首次硬解成功”和“回退后可播”。

编号、降级行为和留存上限已同步到公开契约。

## 已确认公开契约

| 项目 | 约定与边界 |
|---|---|
| 包名 | 公开 API 位于 `com.cn.media.playback`，实现类型收在内部并对外隐藏。首版私库坐标见 D01 已确认决策。 |
| Java/Kotlin 接口 | 共用 Player、PlayerConfig、MediaSource、PlayerListener、PlayerSnapshot、PlayerError；Java 使用普通方法、监听器和不可变对象，Kotlin 直接调用。用显式可空性标注；未知时长可空，公开时间使用毫秒。首版公开 API 不要求协程。异步命令接收成功后返回请求编号，由回调交付唯一终止结果。 |
| 回调线程 | 默认 Android 主线程；允许创建实例时指定 java.util.concurrent.Executor。SDK 为每个实例串行派发，即使传入线程池也保持顺序。监听器内可发下一条命令；不持内部锁调用宿主。 |
| 进度 | 播放中默认每 250 ms 发布一次，可配置 100～1000 ms；0 关闭周期推送。暂停及结束后停止定时推送；定位完成、状态变化和结束立即发布快照。慢消费者只合并尚未交付的周期进度，不合并请求结果、错误或结束事件；旧会话进度失效。 |
| 音量 | 实例线性增益 0.0～1.0，默认 1.0。0.0 无声；静音单独保存，取消静音采用当前设置的增益。拒绝越界、NaN 和无穷值，保留上次有效值；系统媒体音量由宿主管理。 |
| 诊断留存 | 每实例仅在内存保留最近 128 条脱敏诊断，周期进度只保留最新快照；释放后清除。宿主可在释放前读取，默认不持久化。 |

### 错误码及命令结果

对外使用稳定的数值与符号名，发布后不复用编号。每条错误带影响范围（请求、轨道或会话）、失败阶段、原始原因及恢复结果。遇到未来新增错误码时，宿主按范围和通用描述处理。

| 范围 | 已确认编号与名称 |
|---|---|
| 参数、状态、操作能力 | 1001 INVALID_ARGUMENT、1002 INVALID_STATE、1003 SEEK_UNAVAILABLE、1004 TRACK_NOT_FOUND |
| 输入 | 2001 INPUT_PERMISSION、2002 INPUT_IO、2003 INPUT_TIMEOUT |
| 媒体与轨道 | 3001 FORMAT_UNSUPPORTED、3002 TRACK_UNSUPPORTED、3003 INVALID_MEDIA_DATA、3004 NO_PLAYABLE_TRACK |
| 解码 | 4001 DECODER_INIT、4002 DECODER_RUNTIME |
| 输出与资源 | 5001 OUTPUT_LOST、5002 RESOURCE_EXHAUSTED |

CANCELLED 与 SUPERSEDED 作为命令终止结果单列。失败选轨只结束该请求；硬解回退成功保留原始错误与实际后端。无法继续播放才进入会话 Error。

### 单轨可播放的判定

1. 源只有音频或只有视频时正常播放；封面图不算独立视频轨。Surface 暂时解绑沿用 L02 行为。
2. 源有音视频但一类轨道无法播放时，先按已选解码策略尝试允许的恢复。默认在剩余轨上继续，发送一次轨道降级事件，快照列明失效轨、原因和实际活动轨。剩音频沿用已消费采样时钟，剩视频从当前媒体位置接续单调时钟。
3. 提供严格模式：源中已选的音视频轨必须都能播放，否则终止会话。另规定“仅硬解”下所选视频硬解失败按 H04 返回明确失败，不借音频续播掩盖策略失败。全部不可播时报告 NO_PLAYABLE_TRACK 并保留各轨原因。
4. B02 声明必播的双轨样本必须同时验证应有的声音与画面。运行时降级可保证部分播放体验，格式验收仍登记该组合失败。
