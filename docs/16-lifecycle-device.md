## 执行前准备

记录固件、ABI、SDK/宿主版本、音频输出链、屏幕刷新率、Surface 类型和实际后端。准备 V05（两轨分别报轨名）、V01（闪光与短音）、V11（无音轨长 GOP）及 X01 的顺序输入变体。为双音轨准备同一时间轴的报号参考，登记各可用输出设备及可采集位置。启用包含请求、会话、时间轴、轨道、路由与 Surface 版本的事件记录；外部回录与画面标记采用同一校准时基。

## 操作与判定

| 步骤 | 真机操作 | 需要保存的证据和通过条件 |
|---|---|---|
| L01-1 正常换轨 | 播放 V05，从 A 切 B 再切 A；暂停状态下重复。再测试不同采样率或布局的已登记变体 | 对照实际报号、轨道快照及新轨首样本。记录最后旧声至首个新声的间隔及切换后旧轨写入次数；暂停时不出声 |
| L01-2 失败与竞争 | 请求无效轨道，分别在准备和提交后注入失败；另测快速 A→B→A、寻位期间换轨，以及顺序源新轨迟到 | 前置失败可继续听到原轨，提交后结果与实际可听轨一致；每个请求恰有一个结果。记录回滚失败或超时，不能将旧轨标签当作原轨已恢复 |
| L01-3 真实路由变化 | V01 从扬声器播放，接入并拔出耳机。对出货支持的 USB、蓝牙或 HDMI 路由分别重复；记录是否实际改道 | 用设备路由和物理声音两份证据确认声源，测最后旧声、首个新声及 K04 恢复后偏差。连接但未改道单列 |
| L01-4 路由重建 | 分别在播放、静音及暂停时切换路由；另用测试宿主触发旧 AudioTrack 失效 | 音量、静音、选轨和暂停意图保持；恢复后进度无计数归零造成的大跳。记录系统平滑改道或 SDK 重建及各自耗时 |
| L02-1 双后端重绑 | 对 V01 分别强制软解、仅硬解，确认实际组件；主动解绑 A、创建 B 并绑定。另触发一次页面 Surface 真实销毁和重建 | 保存销毁回调返回、旧窗口最后写入/提交、解绑完成和 B 首个可见帧。旧窗口在销毁回调返回后无访问，音频连续，B 画面贴合当前音频位置 |
| L02-2 纯视频与不可定位源 | 两种后端分别播 V11，解绑期间观察冻结位置，分别在期间主动暂停和保持播放意图后重绑；用 X01 测缓存恢复及等待下一关键帧 | V11 只在意图允许时恢复；X01 不回读，记录缓存覆盖、等待时间及实际恢复结果 |
| L02-3 重建竞争 | 快速 A→B→C，硬解分别覆盖直接切换与强制重建；期间发起 seek、切源或 release。软解在有在途绘制时触发销毁 | 新画面仅来自当前会话和输出版本，裁剪与旋转正确。释放后无旧回调或遗留窗口引用；真实平台错误与注入失败分列 |
| 联合回归 | V05 播放中换轨，同时拔插耳机并重建 Surface；随后停止并重新打开 | 核对最终轨道、实际路由、实际 Surface 与播放意图；声画标记与状态一致，FD、线程及 native 内存回落到已确认水位 |
